Crossing JS ↔ WASM

  
Everything below calls into the same module that draws the fractal. Only numbers cross directly; everything else is memory.

  

    

      
Only numbers cross

      
instance.exports.add(a, b) is just a function call. i32 in, i32 out.

      
  

      

    

    

      
i64 arrives as a BigInt

      
JavaScript numbers lose integers above 253. A WASM i64 doesn't, so it crosses as a BigInt.

      

      

    

    

      
Strings are pointer + length

      
Encode to UTF-8, write the bytes into WASM memory, pass the pointer and length. C++ uppercases in place; JS decodes the same bytes.

      

      

      

    

    

      
Arrays too

      
An Int32Array view onto the scratch area; C++ reads it through the pointer.

      

      

      

    

    

      
memory.grow() detaches old views

      
Grow the memory by one 64 KiB page. The old typed array goes dead. Re-create it and it's fine.

      
 

      

    

    

      
What the module exports

      
Everything JavaScript can see. No globals, no DOM, no ambient access: just these.
